# Implementation Plan: ValorBOM v3 UX refactor

Source of truth: `/Volumes/workplace/6800/bom-uploader/.agents/tasks/ux-refactor/design.md` (draft 8, user-approved; `design-approval.json`). This plan sequences the design's increments INC-1 to INC-9 (design section 12). It does not re-decide anything. When this plan and the design disagree, the design wins; section numbers below (§) point into the design.

Progress is tracked in `/Volumes/workplace/6800/bom-uploader/.agents/tasks/ux-refactor/progress.json`. Do one increment per loop iteration, in order, and set its `done: true` only after every verify step for it passes and the commit exists. Set `complete: true` after INC-9.

## Ground rules for every increment

- **Repo root:** `/Volumes/workplace/6800/bom-uploader` (git repo, branch `feature/assembly-build-part`). Every path below is absolute. Run commands with that directory as `cwd`.
- **Baseline (measured while planning):** `npm test` gives 32 suites / 472 tests passing. Every increment must end with all of them still passing, plus the new ones.
- **Build/test commands (from `package.json`):**
  - Server and pure-client tests: `npm test` (`NODE_OPTIONS=--experimental-vm-modules jest`; `testRegex` is `/__tests__/.*\.test\.js$`). Run one file with `npm test -- __tests__/services/partService.test.js`.
  - Client build: `npx vite build --config src/client/vite.config.js` must finish with no errors.
  - Visual (from INC-5): `SHOTS_DIR=.agents/tasks/ux-refactor/screenshots/INC-n npm run test:visual -- --inc INC-n` must exit 0 (it fails on a missing fixture, an axe serious/critical violation, a forbidden word, or a console error; §13).
- **Architecture:** services are DI classes wired in `/Volumes/workplace/6800/bom-uploader/src/server/index.js`; routes are thin `asyncHandler` wrappers calling one service method, validating with `badRequest()`. New BOM routes stay on the ungated surface; `/api/purchasing` and `/api/receiving` stay behind `gate`. Designer and Assembly pages hold their own local state (`useState`/`useReducer`), no new Zustand slices. Visible UI copy uses only Assembly, Build, Part, Revision (no "epic", "story", "issue", "Jira").
- **Safety:** no Jira or OnShape writes during implementation or verification. Tests use mocked clients; Playwright uses fixtures and a Vite proxy pointed at dead port 9. The only live calls allowed are the read-only createmeta probes named in INC-1 and INC-3 (`/tmp/ux-refactor-check/*.mjs`, GET only). Never print or commit `.env`, `.env.authentik`, or `keys.json`.
- **Input safety:** every new key input goes through `validateIssueKey` (INC-2) and `sanitizeJQL` before JQL; OnShape ids are hex-validated; search text never reaches JQL (§6, §10).
- **Inclusive language** in code, comments and docs (allowlist/denylist, primary/replica).
- **Commits:** one Conventional Commit per increment (e.g. `fix(parts): Write Revision on Part create`), staged by explicit path, never `git add -A`/`git add .`. Check `git status --short` first; leave `.kiro/` and `.env.authentik` untracked. Never push.
- **Stop and ask** (send_message severity `warning`) when: a createmeta precondition fails; no Playwright release maps to cached Chromium revision 1228; INC-9 finds a remaining importer of something it must delete.
